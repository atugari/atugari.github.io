# ナンプレ補充係 Android 試作版

ナンプレの未出題在庫を補充する管理者用アプリ。生成はスマホ内で行う。PCや同じWi-Fiへの接続は不要。

1. 自販機の管理画面で端末登録リンクを発行する。
2. Xperiaで登録リンクを開き、「このスマホを登録する」を押す。試験サーバーの接続先は初期設定済みで、登録コードはリンクから入る。
3. スマホを電源と許可した回線につなぐ。従量制回線の利用は初期状態で無効。
4. アプリの「連続補充を今すぐ始める」を押す。電源と回線の条件を満たしていれば、その場で仕事を確認する。
5. スマホにも問題を貯める場合は「端末在庫を作る（オフ）」を押し、条件ごとの目標を設定する。入力欄の初期値は各10問。0問を設定すると自動で作り置きする動作を止める。

試験用のサーバーを使う場合は、登録する前に「接続先を設定」でHTTPSの接続先を指定する。端末の登録権限は登録時の接続先に固定される。登録用QRが設定するのはコードだけ。

連続補充は、通知を伴うAndroidのフォアグラウンドサービスで動く。外部電源につながっていれば、バッテリーの充電が一時停止していても動作する。棚に空きがない間は約1分おきに確認し、画面オフでCPUを起こすのは探索中だけ。電源・許可した通信・温度の条件を外れた場合は連続補充を終了する。「連続補充を停止する」は、アプリ画面と通知の両方にある。通知を許可しなかった場合はアプリ画面から停止できる。

「充電中に自動で補充する」がオンなら、連続補充の終了後もAndroidのJobSchedulerで定期的に補充を確認する。充電や回線、OSの状態で開始は遅れることがある。どちらの方法も止める場合は、連続補充を止めて自動補充をオフにする。画面を消した状態での稼働は、機種ごとに実機で確認する。

生成は75秒を上限の目安とする区切りで実行する。中断された探索は別の種で再試行する。端末在庫は固定の23ルール・427条件を対象に、在庫の少ない条件を順番に回す。回線が切れていても、電源と温度の条件を満たす間は手動の連続補充で作り置きできる。

完成品はSQLiteへ圧縮保存し、条件別の件数と取り出しには索引と集計を使う。データベースと作業領域に32GBの上限を設け、端末の空きが約8GBに近づくと新規保存を停止する。登録情報や受理待ちの完成品は上書き更新で引き継ぐ。受理確認が届くまで完成品を保持し、再送時は割り当てとIDを再利用する。

サイトで配布できる条件は、試験サーバーで検証を有効にした通常9×9の難易度1〜3・18、通常16×16・25×25の難易度1、ジグソー25×25・キラー16×16の難易度1「少し複雑」。対応外の完成品は端末に保存し、検証対象を増やした後に補充に使える。

## ビルド

- Android 8.0 以上、ビルド用 Android SDK 35。
- JDK 17、Gradle 8.7以上、Node.js。
- リポジトリのルートから `cd android/nanpure-vending-worker` に移動し、`gradle assembleDebug` を実行する。
- 生成エンジンはリポジトリ内の公開リリース 2026.11.04.95 からビルド時に取り出す。リリースの候補生成、唯一解確認、難易度判定、証明の再検証を使う。
- エミュレーターでローカルAPIを使う場合は、ビルド時の `NANPURE_REFILL_ENDPOINT` に `http://10.0.2.2:ポート/api/vending/worker` を指定する。
- 組み込みエンジンの軽い検査は `node test-engine.cjs` で実行する。

試作APKを使うには、自販機の補充APIと端末登録コードが必要。既存の生成補助の登録コードとは別。
