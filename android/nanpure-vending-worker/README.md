# ナンプレ補充係 高速版 Android

0.3.0は、旧版0.2.2と同じ端末へ別にインストールする版。
アプリIDを `jp.nanpure.refill.fast` に分け、旧版の登録と端末在庫を残す。
青緑のアイコンと「ナンプレ補充係 高速版」の名前で区別する。

通常9×9、とくにLv18の生成で繰り返す唯一解判定を高速化した0.2.3のソース更新を引き継ぐ。
候補の作り方、難易度の採用条件、完成後の証明検査は変更しない。
最大性能モードの複数Workerでも、それぞれが高速化した判定を使う。
測定条件と結果は [0.2.3の高速化記録](../../docs/nanpure/refill-speed-20261105.md) を参照。
現在は登録設定済みの私用APKの準備中。実際の端末登録が完了するまでは登録済み版として配布しない。

ナンプレの未出題在庫を補充する管理者用アプリ。生成はスマホ内で行う。PCや同じWi-Fiへの接続は不要。

## 登録設定済みAPKの使い方

1. APKをインストールして「ナンプレ補充係 高速版」を開く。初回に専用の端末登録を取り込み、コードやURLの入力、登録リンクを開く操作を省く。
2. スマホを電源と許可した回線につなぐ。従量制回線の利用は初期状態で無効。
3. 「連続補充を今すぐ始める」を押す。必要な場合だけ、Androidの通知許可を選ぶ。
4. 最大性能モードはオン、端末在庫は条件ごとに10問を初期設定する。在庫目標は0・10・100・1,000・10,000問の選択肢からタップで変更できる。任意の数字を指定する入力欄も残す。

自動補充は初期状態でオフ。手動で連続補充を始めるまで処理は開始しない。
「充電中に自動で補充する」は必要に応じてオンにできる。
旧版の端末在庫は旧版の保存領域に残り、新版へ自動では移らない。

私用APKへ入れるのは、新版専用の補充端末トークンだけ。
管理者キーはAPKにも公開ソースにも入れない。設定は初回に一度だけ取り込み、
既に登録済みの端末や変更済みの設定を上書きしない。「登録を解除する」を選んだ後は、
アプリを開き直しても同梱設定から勝手に登録を復活させない。

## 汎用ビルドの登録

私用の登録設定を同梱しない開発用ビルドでは、自販機の管理画面で登録コードを発行する。
高速版の登録リンクは `nanpure-refill-fast://pair?code=登録コード`。
旧版専用の `nanpure-refill://` リンクは高速版で受け取らない。
登録リンクを開いて「このスマホを登録する」を押すか、コードを貼り付けて登録する。

試験用のサーバーを使う場合は、登録する前に「接続先を設定」でHTTPSの接続先を指定する。端末の登録権限は登録時の接続先に固定される。登録用QRが設定するのはコードだけ。

連続補充は、通知を伴うAndroidのフォアグラウンドサービスで動く。外部電源につながっていれば、バッテリーの充電が一時停止していても動作する。棚に空きがない間は約1分おきに確認し、画面オフでCPUを起こすのは探索中だけ。電源・許可した通信・温度の条件を外れた場合は連続補充を終了する。「連続補充を停止する」は、アプリ画面と通知の両方にある。通知を許可しなかった場合はアプリ画面から停止できる。

「充電中に自動で補充する」がオンなら、連続補充の終了後もAndroidのJobSchedulerで定期的に補充を確認する。充電や回線、OSの状態で開始は遅れることがある。どちらの方法も止める場合は、連続補充を止めて自動補充をオフにする。画面を消した状態での稼働は、機種ごとに実機で確認する。

最大性能の並列数は、Androidがアプリに提供するCPU数とメモリの空き、端末温度に応じて決める。予約は同じ条件を複数のWorkerで探索して最初の完成品を使う。すぐ作れる通常Lv.1〜3の予約は1並列で、端末在庫は不足条件を並行して生成する。探索中の温度上昇では並列数を下げる。自動補充は1並列で動作する。完成した盤面は1問ずつアプリに渡し、保存と送信は順番に行う。

生成は75秒を上限の目安とする区切りで実行する。探索に終了を通知してから強制停止までに猶予を設ける。100×100の検証済み小盤面候補は、探索が自分で終了して同じWorkerが動き続ける場合に次の探索へ引き継ぐ。端末在庫は固定の23ルール・427条件を対象に、在庫の少ない条件を順番に回す。回線が切れていても、電源と温度の条件を満たす間は手動の連続補充で作り置きできる。

完成品はSQLiteへ圧縮保存し、条件別の件数と取り出しには索引と集計を使う。データベースと作業領域に32GBの上限を設け、端末の空きが約8GBに近づくと新規保存を停止する。登録情報や受理待ちの完成品は上書き更新で引き継ぐ。受理確認が届くまで完成品を保持し、再送時は割り当てとIDを再利用する。

全条件を有効にした試験サーバーでは、固定の23ルール・427条件の完成品を0.2.0から補充できる。サイトはサーバー在庫が足りない条件の予約も受け付ける。

## ビルド

- Android 8.0 以上、ビルド用 Android SDK 35。
- JDK 17、Gradle 8.7以上、Node.js。
- リポジトリのルートから `cd android/nanpure-vending-worker` に移動する。開発用は `gradle assembleDebug`、配布用の署名前APKは `gradle assembleRelease` で作る。
- 登録設定済みの私用ビルドでは `NANPURE_REFILL_BOOTSTRAP_FILE` に非公開の `device-bootstrap.json` の絶対パスを指定する。形式1、既定の接続先、64桁の小文字16進端末トークンを検査してから、生成アセットへコピーする。環境変数を外した次回ビルドでは前回の設定を削除する。
- 生成エンジンの基盤はリポジトリ内の公開リリース 2026.11.04.95 からビルド時に取り出す。通常9×9の唯一解判定には `engine-overrides/unique-solver.js` を組み込む。候補生成、難易度判定、証明の再検証は基盤のものを使う。
- この判定処理は公開版 2026.11.05.100（commit `cc0068e47e68e15474a65de27eb9a7ae9eb01d00`）の `notebook/unique-solver.js` と同じ内容。既存427条件のキーと保存形式は変更しない。
- エミュレーターでローカルAPIを使う場合は、ビルド時の `NANPURE_REFILL_ENDPOINT` に `http://10.0.2.2:ポート/api/vending/worker` を指定する。
- 組み込みエンジンの軽い検査は `node test-engine.cjs` で実行する。
- 高速化した判定の独立検査と条件定義の一致確認は `node test-unique-solver.cjs` で実行する。

Gradleの依存関係解決を利用できない環境では、取得済みの公式SDKで
`python3 build-apk.py --sdk SDKフォルダ --jdk JDK17フォルダ --out 署名前.apk`
を実行できる。AAPT2、AndroidのJava API stubに対するjavac、D8、zipalignを使う。
私用登録設定を入れる場合は `--bootstrap 制作更新用フォルダ/device-bootstrap.json` を加える。
この手順も許可した項目だけを検査し、アセットへ出力するのは形式・接続先・補充端末トークンの3項目のみ。
外部ライブラリを使う構成へ変更した場合は、手動ビルドを停止してGradleを使う。

初回設定・登録解除・再起動・競合のローカル検査は [tests/bootstrap](tests/bootstrap/README.md) に置いている。
Android実機の画面や通信の試験とは区別する。

試作APKを使うには、自販機の補充APIと端末登録コードが必要。既存の生成補助の登録コードとは別。

## 高速版の署名と今後の更新

高速版 `jp.nanpure.refill.fast` の証明書SHA-256は
`978DF197BC7028EE85CE1F871CDCEC66ACFD21E331C4709F3FD3A45275DA37B4`。
専用の署名鍵と設定を制作更新用の非公開ファイルに保存している。
今後の高速版の上書き更新には、この同じ鍵を使う。新しいdebug鍵で代用しない。

署名前APKに対して `sign-apk.py --apk 入力.apk --out 出力.apk --private 制作更新用フォルダ --sdk AndroidSDKフォルダ`
を実行する。アプリID、整列、署名の検証と証明書の一致確認を行う。パスワードはコマンドラインへ出さない。
管理者キー・端末トークン・秘密鍵・署名用パスワードを公開リポジトリへ保存しない。

旧版 `jp.nanpure.refill` の0.2.2と高速版は別アプリなので、旧版を削除せずにインストールできる。
0.2.3は高速化エンジンのソース更新のみで、旧版と同じ署名のAPKは配布していない。
