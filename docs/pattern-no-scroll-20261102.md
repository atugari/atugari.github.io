# 一画面表示の最大化（2026.11.02.77）

利用者のスクリーンショットでは、一画面表示でも盤面の上に大きな操作欄とサイトの見出しが残り、左右には空きがある一方で、道具・作成状態・見本にはスクロールが発生していました。

- 盤面の上にあった見出し・描画とプレビューの切り替え・作成可否を左側へ移動。一画面表示では盤面が中央の高さ全体を使います。
- サイト本体の中では、編集用iframeを表示領域全体へ広げ、サイト見出しの領域も盤面に使います。通常表示へ戻す、戻る、保存後の画面遷移、ページを離れる際は元のiframe配置へ戻します。ブラウザのネイティブ全画面とは別の表示です。
- 左右の幅を盤面のサイズに合わせて配分します。盤面サイズを変えるのは画面サイズ、表示モード、明示的な大きさ操作だけです。
- 道具は「塗る・消す」「回転・反転」「表示・大きさ」、作業欄は「作成・保存」「作成状態・直し方」「見本」「数字を1種類抜く」「描き方・作成のコツ」で切り替えます。
- 説明はページ送りで全文読め、参考リンクも最後のページから開けます。ページ全体にも操作欄にもスクロールを作りません。
- 縦長のスマホは下の作業欄を切り替えます。横向きのスマホは左右に道具を置き、盤面を縦に押しつぶさない配置にします。操作と説明の文字は16px以上です。

Cloud Browserで1916×784相当の盤面を552pxから768pxへ拡大し、全操作欄のスクロール領域がないことを確認。320×636では296pxの盤面、全8操作欄、描画・取り消し時の同一座標を確認しました。外側のサイト見出しを持つテスト画面ではiframeが画面全体を使い、通常表示で元の位置へ戻ることを確認しました。

CIでは6種類の画面サイズで全操作欄の縦横のはみ出し、ふりがな表示、説明と直し方の全ページ、最大サイズ、描画中の位置固定、保存・再読込を検証します。さらに実際のサイト本体を1534×696と1910×878で開き、見出し領域の回収と元への復帰を確認します。従来の通常表示の描画・保存・数字抜きの検証も継続します。
