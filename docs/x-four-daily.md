# Xへ毎日4問を4回投稿する

投稿時刻は日本時間の8:00・12:00・18:00・21:00です。1投稿に2048×2048の問題画像4枚を添付します。1日4投稿・計16問です。スマホ用アプリやChatGPTの起動は不要です。

## 時刻の管理

2026-10-26から、投稿そのものはCloudflare WorkersのCronで行います。GitHub Actionsは当日から2日先までの未準備枠を事前生成・検証して予約する役割です。GitHub側が数時間遅れても、既に予約した投稿時刻には影響しません。

旧方式では2026-10-25の21時の処理が、翌26日の0時34分に開始されました。旧処理は元の枠の日付を維持していたため、25日分が26日未明に投稿されました。現在は、日付をまたいだ処理や予定時刻から15分を超えた処理を投稿しません。遅れた分の深夜投稿や翌日の埋め合わせも行いません。

CloudflareのCronはUTCで`0 3,9,12,23 * * *`を指定します。日本時間では12時・18時・21時・翌8時です。実際の投稿完了にはXの応答時間が加わります。15分の期限は画像送信中も再確認します。

2026-10-26の8時分は予定どおり起動しましたが、最後の`POST /2/tweets`が400で拒否されました。画像アップロード用の文字列`media`と投稿用のオブジェクト`media`を同じ条件で処理したため、投稿本文と4つの画像IDが送信JSONから失われていたのが原因です。すべての本文を`JSON.stringify`で送るよう修正し、実際に送信するJSONの本文・画像ID・アップロード形式を検証するテストを追加しました。本番のドライランでも送信後のJSONを検査します。8時分の自動再投稿は行わず、以後の予約枠から修正版を使います。稼働確認の`version`は2です。

## 問題・本文

毎日の4種類と難易度は日付に基づく乱数で選びます。同じ日の4回は同じ種類・難易度で、問題は毎回作り替えます。対象は通常・ジグソー・対角線・ハイパー・アンチナイトの各9×9ナンプレ、シルプレ、和同開珎、7×7クロスワードの8種類です。1回のルールは重複させず、数独系は2問までにします。

難易度の表示は「簡単・普通・難しい・とても難しい」です。指定した条件を無断で下げません。数独系の一意解などを生成器とは別の検証処理でも確認します。本文は承認済みの長文を保持します。画像内のURL・QRコード・ルール・ALTも保持します。本文内のURLは`X_FOUR_INCLUDE_URL=true`のときだけ追加します。

2026-10-26に所有者から、4つのX接続情報をCloudflare Worker Secretsにも保存し、投稿処理を移す明示的な許可を受けました。

## 接続とデプロイ

既存の4つのGitHub Secretsを使います。追加のトークン入力は不要です。

- `X_API_KEY`
- `X_API_SECRET`
- `X_ACCESS_TOKEN`
- `X_ACCESS_TOKEN_SECRET`

`CLOUDFLARE_API_TOKEN`は既存のサイトAPIと同じアカウントへのデプロイに使います。専用Worker `nanpure-x-scheduler`を作り、4つのX資格情報をCloudflareの暗号化されたWorker Secretsに渡します。資格情報をソース・画像・公開ログ・データベースへ書きません。Bearer Tokenは不要です。

専用Workerは既存のD1 `puzzle-db`に`x_four_`で始まるテーブルだけを追加します。サイト本体のAPI・問題データ・ランキング用テーブルは変更しません。保管する画像は出題画像だけで、解答データは予約先へ送りません。

GitHubから予約先への認証には2つの既存Secretから専用のSHA-256トークンを導出します。予約・状態参照・画像登録・稼働切替は認証必須です。HTTPから実投稿を強制するエンドポイントはありません。投稿はCronからだけ実行できます。

GitHub Actionsの`X daily four puzzles`は日に4回、3日分の予約を補充します。push時は接続確認・専用Workerのテストとデプロイ・予約補充も行います。`workflow_dispatch`の`queue`は同じ処理を手動実行します。`preview`は画像生成だけ、`check`は接続確認だけです。どのGitHub実行も即時投稿しません。

## 投稿履歴と重複防止

投稿IDは`YYYY-MM-DD@HH:MM`です。予約枠と問題の指紋をD1に記録し、過去のGitHub投稿履歴も移行します。投稿前にその枠を原子的に確保します。同じ枠・同じ問題の重複を防ぎます。投稿結果が不明な場合やXのAPIエラーでは自動再送しません。確保済み枠を解除して再実行する前に、X上に投稿がないことを確認してください。

画像の取り込みが中断された場合だけ、未公開・準備中の同じ枠を安全に作り直せます。投稿済みや送信を開始した枠の差し替えはできません。投稿済み画像は削除し、残った画像も7日後に掃除します。指紋と投稿結果は保管します。補充後はD1の履歴をGitHubの`x-four-history`ブランチにも同期します。

## 停止と再開

ActionsのVariablesで`X_FOUR_POST_ENABLED=false`を設定して、`X daily four puzzles`を`queue`で実行するとCloudflare側の停止設定を更新します。自動補充の次回実行でも反映されます。予約画像を残したまま投稿を止めます。`true`に戻して`queue`を実行すると、以後の予定枠から再開します。期限切れの枠は再投稿しません。

クレジット不足でも同じ枠を自動再送しません。入金後は次の予定枠で再び投稿を試みます。Xの自動チャージや支出設定は変更しません。
