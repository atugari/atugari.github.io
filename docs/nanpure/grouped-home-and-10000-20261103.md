# ホーム整理と1万問保存の検証

リリース: 2026.11.03.87

ホームに目的別の枠と色を付け、「遊ぶ・作る・学ぶ」「記録と達成」「作品を楽しむ」を並べた。問題集・作成・学習・ランキング・自分の記録・カレンダー・称号・保存・お問い合わせは実際の既存機能につながる。デザイン選択は既存の3テーマに従う。

画面幅による自動表示と、横向きスマホで使えるPC表示をヘッダーと設定に追加した。選択は保存され、プレイ用フレームにも引き継ぐ。幅500px未満では読みやすい縦配置を維持し、通常の問題盤と操作部の横配置は600px以上で適用する。盤面ズームや数字キーの個別設定とは別の表示設定である。

## 測定方法

検証用の別名IndexedDB・localStorageに、通常9×9を9,999件と100×100を1件投入。旧v2から移行し、実際の配布版ストレージ・画面・入力・印刷・復元を動かした。さらに配布版の生成エンジンで通常9×9・難易度1を10問作り、1万件がある状態に追加保存した。実際の利用者のデータは読み取っていない。

固定の問題盤面を元にした1万件の負荷用データであり、異なる難問を1万問生成した実験ではない。

| 処理 | 今回の測定 |
|---|---:|
| 初回だけの旧保存方式からの移行 | 5.04秒 |
| 次回以降の一覧データ読み込み | 0.10秒 |
| 実際の問題帳の起動 | 0.31秒 |
| 一覧24件のDOM作成 | 0.041秒 |
| 数字入力から保存まで | 0.013秒 |
| 追加生成した1問の保存（平均） | 0.0026秒 |
| 圧縮済みの自動退避スナップショット | 0.16秒 |
| 従来形式の全問バックアップ構築（10,010件） | 0.48秒 |

一覧プレビューはSVGを画像として表示し、24盤面の大量のマスや数字を操作対象のDOMに展開しない。条件検索・一覧作成の同期処理は、変更前約56〜65ms、変更後約28〜40msだった。画像が実際に読み込まれることも検証した。

一覧には問題本体・解答・メモを展開せず、プレイでは選んだ1問、印刷では選んだ2問だけ読み込む。保存失敗のロールバック、未保存入力の保持と再保存、再開時の数字と候補メモ、圧縮バックアップと旧形式バックアップの復元も成功した。

## 判断と限界

今回の条件では、1万件の保有が通常の入力・保存を重くする問題は再現しなかった。初回移行は数秒かかる。全件バックアップや複雑な生成は一覧閲覧とは処理が異なる。

測定はリモートChromeで行い、スマホ実機のメモリ不足・発熱・省電力モードを再現していない。一覧DOM作成の数値はペイントや画像デコードの完了時間を含まない。バックアップの数値はスナップショット構築までで、ダウンロードやクラウドへの転送は含まない。追加生成10問はいずれも通常9×9・難易度1であり、大盤面や難問1万問の生成時間へは外挿できない。

再実行: 配布サイトをローカルに組み立てた後、`NP_STORAGE_FIXTURE=fixtures/nanpure-10000-storage.html node scripts/check-nanpure-lazy-storage-browser.cjs _site`。追加生成を含める場合は検証ページのURLに `?generation=1` を付ける。実データに触れないルーティングとスコープ分離を維持すること。
