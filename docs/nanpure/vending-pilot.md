# ナンプレ帳「問題の自販機」試験版

通常9×9・難易度18「至高」の未配布問題を扱う。利用者は在庫から受け取り、足りない分を予約できる。受け取った問題は、同じサイトにある端末内の問題帳に保存する。予約と取り置きは申し込んだブラウザの識別キーで確認する。

## パレードの操作

1. 自販機の補充担当者画面を開き、ナンプレ帳の管理者キーで接続する。
2. Xperiaに試験版の補充アプリを入れる。端末ごとに登録コードを1つ発行し、補充アプリで登録する。
3. 補充を有効にし、端末を充電と利用可能なネットワークにつなぐ。初期設定では従量制でない接続で動作する。
4. 管理画面の在庫、予約の不足分、作業中の端末を確認する。利用者側からの予約は、同じブラウザで受け取り状況を確認できる。

補充アプリはインターネット経由で直接仕事を受け取る。端末同士のWi-Fiをそろえる必要はない。完成した問題は入庫確認までスマホに保持する。途中で中断した探索は新しい候補から再開する。画面を消した後の実行時刻はAndroidが調整する。

## 在庫と検証

- 試験時の棚は10問未満で補充を開始し、一般在庫30問を目安に補充する。未処理の予約を先に満たし、進行中の仕事を差し引いて重複発注を抑える。
- スマホが配布版の生成エンジンで難易度を判定する。サーバーは送信元の登録、仕事の割り当て、盤面・唯一解・論理証明を再確認してから入庫する。負荷の高い難易度の再探索はスマホ側に置く。
- 在庫と予約は試験用のテーブルに記録する。日替わりの出題データとは分けて管理する。
- 同じ申し込みや同じ完了結果を再送しても、同じIDで処理する。割り当ての期限を過ぎた仕事は別のスマホが取得できる。
- 一度に申し込める数は1〜10問。受け取りが完了しない申し込みは、7日経過後の整理処理で期限切れとなる。未受取の取り置きは、別の予約か一般在庫に戻る。

## 試験環境

`VENDING_ENABLED=1` の環境で試験用のD1マイグレーションを適用するとAPIが有効になる。初回は専用のD1と試験用の管理者キーを使う。管理者キーそのものはWebページやAPKに埋め込まず、サーバーの `OWNER_KEY_HASH` にはSHA-256のハッシュを設定する。

| 場所 | 役割 |
| --- | --- |
| `/nanpure/vending/` | 在庫・予約・受け取り |
| `/nanpure/vending/owner.html` | 補充担当端末の登録と停止 |
| `/api/vending` | 利用者向けAPI |
| `/api/vending/admin` | 管理者向けAPI |
| `/api/vending/worker` | スマホ向けAPI |

開発環境で `cd nanpure-api && npm test` を実行すると、固定した配布版から証明の検証モジュールを作り、APIをテストできる。GitHub Pagesの公開元と同じオリジンに画面を置くと、その端末の既存問題帳を利用できる。別オリジンの試験画面は独立した端末内ストレージを使用する。

ブラウザで一連の動作を確認するには、検証モジュールの生成後に、ChromiumとPlaywrightを用意してルートから `node scripts/check-nanpure-vending-browser.cjs` を実行する。既定ではテスト用のローカルDBを使用する。

実機試験はPCを切り、別々の回線に接続したXperia 2台で行う。片方を途中で停止し、仕事の再割り当てから予約者の問題帳への保存までを確認する。端末のバックグラウンド動作と通信量はこの試験で測る。
