# ナンプレ補充係 0.2.3：生成処理の高速化

## 状態

2026年11月5日（日本時間）のソース更新。配布済みAPKは0.2.2。
0.2.3はエンジンの改修とPC上の検証まで完了し、Android APKの再ビルド・同一署名・実機確認は未完了。
更新APKを配布済みとして扱わない。

## 変更

通常9×9、とくにLv18の生成が繰り返す唯一解判定を高速化した。
公開サイト版2026.11.05.100の `unique-solver.js` を、補充係の固定エンジン2026.11.04.95の
`core-normal` の直後に組み込む。候補の作り方や難易度を採用する条件は変えない。

判定処理は候補を伝播し、探索中の変更だけを記録して巻き戻す。
通常9×9の解の個数を正確に数え、2個以上の解があれば唯一解として受け入れない。
完成後の盤面検証と解き方の証明の再検証も従来どおり行う。

ビルド時の入力一覧へ判定処理を追加し、最大性能モードの各Workerにも同じ処理を読み込ませる。
版番号は `0.2.3` / `versionCode 7`。ネイティブ側、保存形式、通信先、予約、再送、
温度・空きメモリによる並列数制御、既存の中断・Worker再利用は変更しない。

## 比較結果

Linux x64、Node.js v24.22.1、Intel Xeon Platinum 8573C、CPU割当8コアの同じ環境で測定。
Xperia実機やAndroid WebViewでの測定ではない。
単体比較は毎回新しいWorkerを作り、エンジンの読み込み時間を除外し、旧版・新版の実行順を交互にした。
候補と論理評価の同一性を確かめる計測用ログは両版で同じように追加した。

| 比較対象 | 0.2.2 | 0.2.3のエンジン | 結果 |
| --- | ---: | ---: | --- |
| Lv18、固定ID `Xperi` の1問完成、3回の中央値 | 8.902秒 | 3.100秒 | 約65.2%短縮、約2.87倍の速度 |
| Lv18、固定ID `aBc12` の先頭5探索、3回の中央値 | 3.916秒 | 0.910秒 | 約76.8%短縮。同じ作業量の比較で、1問完成までの時間ではない |
| Lv18、8並列の1ラウンド、各版1回、15秒上限 | 15秒で未完成 | 9.788秒で1問完成 | 全8 Workerへの適用と、完成品の検証を確認 |
| Lv16、固定ID `aBc12` の先頭5探索、3回の中央値 | 4.896秒 | 5.330秒 | 改善を確認できず。この区間は唯一解判定0回 |

Lv18 `Xperi` は同じ1問を3回ずつ計測した結果。異なる多数の問題の平均ではない。
旧版は8.902 / 8.509 / 8.991秒、新版は3.378 / 3.057 / 3.100秒。
3回とも唯一解判定2,329回・論理評価1,036回が一致し、候補列、判定結果、完成物全体のハッシュも一致した。
完成物はLv18、24ヒント、87手の証明を持ち、証明の再検証にも通った。

8並列の比較は、アプリの元の `bridge.js` → `round.js` → エンジンを
Nodeの8 Workerで実行したもの。Androidネイティブ側、JNI、通信、SQLiteへの保存は測定していない。
新版の完成品は単体比較の `Xperi` と盤面・証明が一致した。
旧版が15秒で完成しなかったため、この比較から正確な短縮率は算出しない。

Lv16の完成比較では3 IDを対象にしたが、両版で完成したのは `Aud16` のみで、
8.494秒→8.835秒だった。唯一解判定は1回、論理評価648回で、完成物と評価結果は一致した。
残る2 IDは上限で未完成。全ルール・全難易度が一律に速くなるという結果ではない。

## 正しさと互換性の検査

- 0.2.2の再構築エンジンが、配布APKに入っていた `engine.js` とバイト単位で一致。
- 固定23ルール・427条件の定義全体が旧版と一致。全427条件を再生成した試験ではない。
- 独立した別の数独ソルバーとの120盤面比較に合格。入力の保持、重複した数字、不正値、解数上限の既存挙動、二重読み込みも確認。
- 既存の `test-engine.cjs` に合格。代表条件の生成、期限終了の返答、並列の先着採用、逐次受け渡し、Worker再利用、古い返答の無視を確認。
- 固定IDを使った旧版・新版の候補列、論理評価、完成盤面、難易度、証明の一致を比較。
- 全8 Workerで `fastUniqueVersion === 1` を確認。
- ビルド入力、各Workerへの組み込み、保存・通信に差分がないことを別担当が静的レビュー。

## 再現方法

リポジトリの `android/nanpure-vending-worker` で実行する。

```sh
node test-unique-solver.cjs
node test-engine.cjs
node benchmark-speed.cjs suite --out /tmp/refill-speed-results.json
```

計測は必要時のみ行う。`prefix`、`complete`、`parallel` で範囲を絞れる。
`verify` は元APKの既知ハッシュと条件定義を照合し、重い生成計測は行わない。
出力先は `--out`、アプリの場所は `--app` で指定できる。
元APKから取り出したエンジンがあれば `--apk-engine` でバイト比較も行える。

詳細な測定値は [refill-speed-20261105.json](refill-speed-20261105.json) に保存。
