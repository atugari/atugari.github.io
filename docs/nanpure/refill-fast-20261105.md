# ナンプレ補充係 高速版 0.3.0

## 現在の状態

専用の補充端末を1件登録し、登録設定を含む私用APKのビルド・署名・検証を完了した。
管理APIで新しい端末が有効であることと、既存の端末登録が維持されていることを確認した。
登録コード・URLの入力や、登録リンクを開く操作は不要。

完成ファイルは `nanpure-refill-fast-0.3.0.apk`、263,090 bytes。
SHA-256：`10428ce4629bde912a8d26e5e536ccb4732d58f31979f22240263db8616b61dd`。
端末専用の登録情報を含むため、APK自体は非公開で渡し、公開リポジトリには保存しない。

## 旧版と共存する版

ユーザーは、旧版0.2.2と端末在庫を残して別インストール版へ移行することを承認し、
入力と登録リンクの操作を省き、登録済みで開ける構成を希望した。

| 項目 | 旧版 | 高速版 |
| --- | --- | --- |
| アプリID | `jp.nanpure.refill` | `jp.nanpure.refill.fast` |
| 最新の配布・準備状況 | 配布済み0.2.2 | 登録設定済み0.3.0の私用APK完成 |
| 名前 | ナンプレ補充係 | ナンプレ補充係 高速版 |
| アイコンの色 | 紫 | 青緑 |
| 登録リンク | `nanpure-refill://pair` | `nanpure-refill-fast://pair` |
| 保存領域 | 旧版専用 | 高速版専用 |

Javaのnamespaceは既存の `jp.nanpure.refill` を維持し、ManifestのActivityとServiceは完全修飾名にした。
設定・在庫・通知・JobSchedulerは新しいアプリの領域を使う。
旧版の在庫を読み出したり削除したりする処理は追加していない。自動移行もしない。

## 入力を省く構成

専用の補充端末登録を済ませ、接続先とその端末用トークンだけを非公開の設定として同梱した。
管理者キーをAPKや公開ソースへ入れることはしない。
初回に設定を取り込み、登録コード・URLの入力、リンクを開く操作、登録ボタンを押す操作を省く。

初期設定は、最大性能モードがオン、端末在庫が条件ごとに10問、自動補充はオフ、従量制回線もオフ。
利用者が「連続補充を今すぐ始める」を押すまで生成を開始しない。
在庫目標は0・10・100・1,000・10,000問からタップで選べる。任意の数を指定する入力も残す。

初回設定には次の保護を入れている。

- 既に登録済みの設定を上書きしない。
- 利用者が変更した在庫数・性能設定・通信設定を再起動で戻さない。
- 登録を解除した後は、同梱設定を再び取り込まない。
- 接続先はビルド時と実行時の両方で既定のサーバーと一致するか検査する。
- ビルド時は許可した項目だけを受け付け、APKに入れるのは形式番号・接続先・補充端末トークンの3項目だけ。
- 接続先だけを変更した増分ビルドでも、設定の検査を再実行する。

## 高速化の引き継ぎ

0.2.3で検証した通常9×9の高速な唯一解判定を引き継ぐ。
今回のAPK内エンジンは、[既存の性能比較](refill-speed-20261105.md)で使ったものとバイト単位で一致した。
同じLv18の1問をPCで3回作った比較の中央値は、旧版8.902秒に対して3.100秒。
この値はXperia実機の速度を示すものではなく、全条件の改善を保証するものでもない。

## ビルドと検証

Gradleの依存関係取得が実行環境の通信設定で完了しなかったため、
公式SDKのAAPT2、javac、D8、zipalignを使う再現可能な `build-apk.py` を追加した。
JavaのコンパイルにはAndroidのAPI定義を使い、ホストJDKだけにあるAPIを混ぜない。
署名は保存済みの専用鍵を使う `sign-apk.py` で行う。

| 検査 | 結果 |
| --- | --- |
| アプリID・版 | `jp.nanpure.refill.fast`、0.3.0、versionCode 8 |
| SDK | min 26、target/compile 35 |
| 起動Activity・Service | 完全修飾名で一致 |
| debuggable・allowBackup | 両方false |
| APK整列・ZIP CRC | 合格 |
| APK署名 | 検証合格、制作資料の証明書と一致 |
| 登録設定の同梱 | 私用APKに3項目を同梱し、登録済み端末の情報と一致 |
| 最終APKの独立検証 | 33項目すべて合格。管理者キーの非同梱も確認 |
| ネイティブクラス | 主要10クラスをDEXで確認、検査用クラスは未同梱 |
| エンジンと条件定義 | 検証済みのSHA-256と一致、23ルール427条件 |
| 初回設定のローカル検査 | 13ケース、228項目合格 |
| 私用設定のビルド検査 | 合成データによる11件合格 |

13ケースでは初回登録設定、再起動、手動登録との競合、解除後の再起動、保存失敗、
壊れた設定、同時適用などを検査した。アプリの実物ソースをコンパイルし、
SharedPreferencesとAssetManagerだけを模擬している。Android実機での画面・SQLite・通信試験ではない。

## 初回の操作と利用範囲

1. 私用APKをインストールし、「ナンプレ補充係 高速版」を開く。登録設定は自動で取り込む。
2. 外部電源と、Wi-Fiなど許可した回線につなぐ。
3. 「連続補充を今すぐ始める」を押す。Android 13以降で通知の確認が出る場合は許可を選べる。

起動しただけでは補充を始めない。旧版を自動で停止する処理もないため、
旧版で補充している場合は旧版を停止してから高速版を開始する。旧版の在庫は残る。
この私用APKは登録したXperia 1台用。同じAPKを複数台へ入れると登録情報を共有するため、
複数台で使う場合は端末ごとに別の登録情報を用意する。

今回確認したのはサーバー登録、APKの署名・構成・設定の一致とローカル試験。
Xperia実機でのインストール、画面、通信、継続動作は未確認。
